SaveAsPDF — מדריך למנהלי מערכת

מסמך טכני להגדרת השרת, מדיניות חותמת, אבטחה ופתרון תקלות.
לממשק הניהול · למדריך המשתמש

1. סקירה

ממשק הניהול של SaveAsPDF מאפשר:

  • הגדרת תיקיית הבסיס (Projects Root) שתחתיה נמצאות תיקיות הפרויקטים.
  • קביעת מדיניות (Policy) חותמת — אילו שדות ייאלצו תמיד-ON או תמיד-OFF, ואילו יישארו לבחירת המשתמש.
  • שינוי שם משתמש וסיסמה לכניסה לממשק.
  • בדיקת פרויקט (Probe) לאיתור בעיות תצורה.

ההגדרות נשמרות בקובץ JSON אחד בשרת: %LOCALAPPDATA%\SaveAsPDF\settings.json.

2. אימות וגישה

ממשק הניהול וכל ה-endpoints הניהוליים מוגנים ב-HTTP Basic Authentication. בכניסה ראשונה הדפדפן יבקש שם משתמש וסיסמה — הזן/י את ברירת המחדל:

שם משתמש: admin
סיסמה: admin
⚠ חשוב: שנה/י את הסיסמה מיד לאחר ההתקנה הראשונית. כל עוד הסיסמה היא ברירת המחדל, רצועת אזהרה צהובה תופיע בראש דף הניהול.

נתיבים מוגנים

נתיבהגנה
/admin/*דורש Basic Auth
/api/settingsדורש Basic Auth (GET ו-POST)
/api/admin/*דורש Basic Auth
/api/info, /api/policyפתוח (התוסף משתמש בהם ללא אימות)
/api/saveaspdfפתוח (התוסף שולח שמירות ללא אימות)
/api/project/*, /api/contacts, /api/folders/*פתוח
/help/*פתוח

3. שינוי סיסמה

  1. היכנס/י ל-/admin (אם זו פעם ראשונה — admin/admin).
  2. גלול/י לכרטיס Admin Account.
  3. שנה/י Username אם רוצה (אופציונלי).
  4. הזן/י New Password (לפחות 4 תווים).
  5. לחץ/י Update Credentials.
  6. הבקשה הבאה תדרוש את הסיסמה החדשה — הדפדפן יבקש להתחבר מחדש.

איפוס שכחת סיסמה

אם אבדה הסיסמה, ערוך/י ידנית את %LOCALAPPDATA%\SaveAsPDF\settings.json בשרת ומחק/י את כל מקטע "admin". בפעם הבאה תוכל/י להיכנס שוב עם admin / admin: 

{
  "projectsRoot": "J:\\",
  "stampPolicy": {...}
  // הסר את "admin": {...}
}

אין צורך באתחול השרת — ההגדרות נטענות מחדש בכל קריאה.

אבטחה טכנית

  • הסיסמה נשמרת hashed עם PBKDF2-SHA256, 100,000 iterations, מלח 16 בייט.
  • הסיסמה הגולמית אינה נכתבת מעולם לדיסק.
  • השוואה בזמן קבוע (CryptographicOperations.FixedTimeEquals) למניעת timing attacks.
HTTP, לא HTTPS: השרת רץ על HTTP (פורט 5176 כברירת מחדל). עבור ייצור — מומלץ למקם מאחורי reverse proxy (IIS / nginx) עם תעודת SSL, אחרת הסיסמה עוברת בטקסט גלוי על הרשת.

4. תיקיית הפרויקטים

השדה Projects Root Folder בכרטיס "Settings" מגדיר את נתיב הבסיס של כל הפרויקטים. ערך אופייני: J:\.

אם הכונן לא זמין כעת

אם הנתיב אינו זמין במכונת השרת בעת השמירה (כונן רשת מנותק וכו') — ההגדרה תישמר בכל זאת, ותוצג הודעת אזהרה צהובה לצד "Saved":

Saved. Projects root = J:\
Warning: folder does not exist or is offline: J:\

זה מאפשר לקבע את כל ההגדרות בלי שתלות בזמינות הכונן ברגע השמירה. כשהמשתמש ינסה לשמור PDF דרך התוסף וה-J: מנותק — תופיע שגיאה אמיתית עם הקשר.

5. מדיניות חותמת (Stamp Policy)

טבלת המדיניות בכרטיס "Settings" כוללת 8 שדות (האב הראשי + 7 שדות החותמת). לכל שדה ניתן לבחור אחת משלוש אפשרויות:

אפשרותאפקט בתוסףאפקט בשרת
User המשתמש בוחר חופשי הערך מהבקשה נשמר כמו שהוא
Force ON תיבת הסימון נעולה למצב דלוק עם 🔒 השרת מחליף את הערך ל-true גם אם הבקשה שלחה false
Force OFF תיבת הסימון נעולה למצב כבוי עם 🔒 השרת מחליף את הערך ל-false

אכיפה דו-שכבתית

  • שכבה 1 (UX): התוסף קורא את /api/policy בעת הטעינה ומשתק את התיבות הנעולות בלוח ההגדרות.
  • שכבה 2 (אבטחה): לפני יצירת ה-PDF, ה-controller מפעיל StampPolicy.ApplyTo(stamp) ומחליף ערכים שננעלו — אפילו אם לקוח שולח בקשה ידנית עם ערכים אחרים, הם יידחו.

זיהוי בקובץ ה-PDF

כאשר מדיניות הוחלה על הבקשה, החותמת בתחתיתה מציגה הודעה קטנה באפור: "[נעול] חלק מהשדות נקבעו על-ידי מנהל המערכת".

שיקולי שמירה

אחרי לחיצה על Save, הטבלה מתרעננת מתוך התשובה של השרת — מה שאתה רואה זה מה ש-settings.json קלט בפועל. אם משהו לא נשמר, סימן שיש בעיה — בדוק את סעיף פתרון התקלות למטה.

6. בדיקת פרויקט (Probe)

בכרטיס "Settings" יש כלי בדיקה: הזן/י מספר פרויקט (לדוגמה 1000-2-1) ולחץ/י Probe. השרת ינסה לפתור את הנתיב לפי הכללים ולהציג:

  • סטטוס (קיים / לא קיים)
  • הנתיב המלא הצפוי
  • שם הפרויקט (מתוך .SaveAsPDF_Project.xml)
  • הערות פרויקט
  • רשימת עובדים (מתוך .SaveAsPDF_Emploeeys.xml) — מנהל מסומן בתג צהוב
  • כפתור להצגת ה-JSON המלא לצורכי דיבאג

שימושי לוודא ש:

  • הנתיב מתורגם נכון לפי floor(num/100)
  • קבצי ה-XML של הפרויקט קיימים ובפורמט תקין
  • רשימת העובדים נקראת כראוי

7. מבנה תיקיות הפרויקט

מספרי פרויקט ממופים אוטומטית לתיקיה ב-2 רמות: 

{ProjectsRoot}\{floor(num/100):D2}\{num}\

דוגמאות:

מספר פרויקטנתיב
123J:\01\123\
1000J:\10\1000\
1234J:\12\1234\
1000-2-1J:\10\1000-2-1\ (החלק הראשוני בלבד נחשב לרמה 1)

קבצי שמירה בתיקיית הפרויקט

  • YYYYMMDD_HHmm_subject.pdf — הודעת ה-PDF
  • קבצים מצורפים — ישירות בשורש (או בתת-תיקיה שנבחרה)
  • בהתנגשות שמות: file.txt → file(1).txt → file(2).txt...

8. קבצי XML של פרויקט

בכל תיקיית פרויקט יכולים להופיע (אופציונלי) שני קבצים:

.SaveAsPDF_Project.xml

פרטי הפרויקט. נטען אוטומטית בעת הקלדת מספר הפרויקט בתוסף.

<?xml version="1.0"?>
<ProjectModel>
  <ProjectNumber>1000</ProjectNumber>
  <ProjectName>פרויקט לדוגמה</ProjectName>
  <ProjectNotes>הערות חופשיות...</ProjectNotes>
</ProjectModel>

.SaveAsPDF_Emploeeys.xml

רשימת עובדי הפרויקט (כן, השם המקורי מכיל שגיאת כתיב).

<?xml version="1.0"?>
<ArrayOfEmployeeModel>
  <EmployeeModel>
    <Id>1</Id>
    <FirstName>ישראל</FirstName>
    <LastName>ישראלי</LastName>
    <EmailAddress>israel@example.com</EmailAddress>
    <PhoneNumber>050-0000000</PhoneNumber>
    <IsLeader>true</IsLeader>
  </EmployeeModel>
</ArrayOfEmployeeModel>

10. פריסה ועדכונים

הפעלה

cd C:\Dev\SaveAsPDF\SaveAsPDF.Web\SaveAsPDF.Backend
dotnet build
dotnet run

השירות מאזין ב-http://localhost:5176 כברירת מחדל.

עדכון לאחר שינוי קוד

  1. עצור/י את התהליך הרץ (Ctrl+C בחלון המסוף).
  2. dotnet build — אם התהליך עוד רץ, ייכשל עם "file in use".
  3. dotnet run --no-build — להעלאה מהירה לאחר build מוצלח.
שכיח: שינויי StampInfo, StampPolicy או PdfService דורשים rebuild + restart. פוס לעדכן את ה-frontend בלבד (taskpane) לא יספיק — ה-backend הישן יתעלם משדות חדשים.

גיבוי הגדרות

כל ההגדרות (כולל hash הסיסמה) נשמרות בקובץ אחד: %LOCALAPPDATA%\SaveAsPDF\settings.json. גבה את הקובץ הזה לצורך שחזור תצורה במקרה של תקלת מערכת.

11. פתרון תקלות

הסימפטוםהסיבה / הפתרון
הגדרות לא נשמרות בממשק הניהול השרת רץ עם בינארי ישן (לפני העדכון שמטפל ב-StampPolicy). עצור/י את התהליך, הרץ dotnet build, והפעל מחדש.
"Build FAILED — file is locked by SaveAsPDF.Backend (PID xxxx)" התהליך הקיים מחזיק ב-SaveAsPDF.Backend.exe. עצור/י אותו דרך המסוף הרץ או דרך Stop-Process -Id xxxx -Force.
בקשת אימות מתפרצת על כל בקשה הדפדפן זוכר Basic Auth רק עד סגירת החלון. אם הכניסה מתבקשת על כל מסך — ייתכן שמשהו ב-cache נמחק. הקלד שוב את שם המשתמש והסיסמה.
שכחתי את הסיסמה ערוך/י את %LOCALAPPDATA%\SaveAsPDF\settings.json ומחק/י את מקטע "admin". ברירת המחדל admin/admin תחזור.
"Folder does not exist: J:\\" בעת השמירה כונן ה-J: לא ממופה במכונת השרת. ההגדרה תישמר בכל זאת. בעת שמירת PDF התוסף יקבל שגיאה ויראה אותה למשתמש. ודא/י שהשרת רץ עם הרשאות הולמות לכונן הרשת.
התוסף לא רואה את ה-Stamp Policy שהוגדרה התוסף קורא מ-/api/policy בעת טעינת הלוח. ייתכן ש-cache. סגור/י וחזור/י לפתוח את הלוח, או הפעל מחדש את Outlook.
PDF נשמר אך אין אכיפה של מדיניות ודא/י ש-settings.json מכיל מקטע stampPolicy עם ערכים שאינם null. בדוק/י עם: 
curl http://localhost:5176/api/policy
שגיאת CORS בעת קריאה מ-https://localhost:3000 במצב פיתוח Webpack DevServer רץ על 3000, ה-backend על 5176. הוגדר CORS ב-Program.cs שמתיר את 3000. אם החלפת פורט — עדכן/י את ה-policy.
